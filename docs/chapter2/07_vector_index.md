# 第 7 章 向量库构建：embedding 与 FAISS

> **本章目标**：理解 embedding 选型、归一化与内积/余弦的等价关系，
> 以及"按公司分库"这一架构决定对检索层的意义。
> 分治策略：整个语料被分治成 **每公司一份独立索引**，检索层据此做精确路由。

## 7.1 实现导读：VectorDBIngestor

`src/ingestion.py`：

- `_get_embeddings`（第 113 行）：OpenAI `text-embedding-3-large`，
  **每批 ≤1024 条**（接口上限）；空字符串直接抛错（OpenAI 对空输入返回占位向量，
  混入库会污染所有查询）；tenacity 重试 2 次、间隔 20s，耗尽则中断整批——
  **残缺索引宁可重跑**（半成品 .faiss 会误导检索端）
- `_create_vector_db`（第 144 行）：`faiss.IndexFlatIP`（内积）。OpenAI
  text-embedding-3 系列默认输出**单位化向量**，故内积 == 余弦相似度；
  若换用未归一化模型，必须先 L2 归一化
- `process_reports`（第 164 行）：逐报告建索引，按 `sha1_name` 写
  `vector_dbs/{sha1}.faiss`——**文件主名即报告标识**，检索端按"同名配对"
  把文档 JSON 与索引对上

## 7.2 为什么按公司分库

不在一个大索引里加公司过滤，而是**每公司一份小索引**：

1. **路由即过滤**：题目都指定了公司（subset.csv 提供 sha1→公司名映射），
   查哪份库由公司名决定，精确、零计算
2. **IndexFlatIP 是暴力全扫描**——精确分数、零近似误差；年报规模
   （百页 × 几十块）完全可承受，无需 IVF/HNSW 近似索引
3. **工程简洁**：每库独立成文件，重建/排障/并排实验（`databases_ser_tab`）
   都以公司为单位

> **动手**
> 1. 用脚本读一份 `.faiss`，验证索引行数 == chunked JSON 里 chunks 数组长度。
> 2. 手动查询一个向量，确认内积分数与 `np.dot` 结果一致（都基于单位化向量）。
